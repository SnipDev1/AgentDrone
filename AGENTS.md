# AGENTS.md — Память проекта и правила разработки

Этот файл определяет соглашения, команды и правила для разработчиков и ИИ-агентов (паттерн Claude MD Memory / Project Memory).

---

## 1. Архитектурный стек
* **Язык:** Python 3.10+ (текущая версия: Python 3.14).
* **CV/ML:** OpenCV, PyTorch / Ultralytics YOLOv8 / PIL, Scikit-learn.
* **LLM / GenAI:** GigaChat API (официальный SDK `gigachat` / REST API Сбера по client_id / secret).
* **Backend & Logic:** Pydantic v2 (валидация данных и контрактов), Jinja2 (шаблонизация Актов).
* **Web UI:** Streamlit / FastHTML (быстрый интерактивный дашборд инспектора).
* **Тестирование и линтинг:** `pytest`, `flake8` / `ruff`, `mypy`.

---

## 2. Команды для запуска и верификации (Executable Guardrails)
Все изменения ОБЯЗАНЫ проходить локальную верификацию перед коммитом:

```bash
# Установка зависимостей
pip install -r requirements.txt

# Запуск тестов
pytest tests/ -v

# Линтинг кода (жюри хакатона проверяет качество кода автоматически!)
flake8 src/ tests/ --max-line-length=100
# или
ruff check src/ tests/

# Запуск интерактивного UI
streamlit run src/ui/app.py
```

## 3. Правила и паттерны разработки (Agentic Coding Patterns)
1. **Explore - Plan - Code - Commit:** Никогда не писать код вслепую. Сначала исследовать данные/код, составить план, реализовать, запустить тесты, сделать атомарный коммит.
2. **One Feature at a Time:** Реализовывать строго по одной задаче из `FEATURE_LIST.md`. После завершения задачи — запустить тесты, обновить `FEATURE_LIST.md` и сделать запись в `PROGRESS.md`.
3. **Tracer Bullet First:** Первый приоритет команды — пробить сквозной рабочий путь (Tracer Bullet): `1 тестовый объект с дрона -> геовалидация -> расчет % готовности -> выбор стратегии -> генерация PDF-акта -> показ в UI`. После этого навешивать точность и фичи.
4. **Executable Guardrails:** Любой новый алгоритм (детекция, расчет %, правила выбора стратегии, генератор отчета) должен иметь юнит-тест в `tests/`. Без теста фича не считается готовой.
5. **No Hallucinations / Strict Schemas:** Входные и выходные структуры описываются через Pydantic-модели в `src/models/`. Никаких «сырых» невалидированных словарей.
6. **Writer - Reviewer:** Разработчик пишет код с ИИ-агентом; второй участник (или агент в отдельном контексте) делает ревью на соответствие `DOMAIN.md` и отсутствие регрессий.

## 4. Структура директорий проекта
```
AgentDrone/
├── DOMAIN.md                # Словарь терминов и предметная область
├── AGENTS.md                # Память проекта и правила кодинга
├── FEATURE_LIST.md          # Список задач и статус их готовности
├── PROGRESS.md              # Журнал прогресса команды и текущие блокировки
├── requirements.txt         # Зависимости Python
├── data/                    # Примеры данных (кадастровые папки, реестр кредитов)
│   ├── registry.json        # Синтетический реестр 13 объектов для хакатона
│   └── samples/             # Тестовые фото и MRK-файлы
├── src/
│   ├── models/              # Pydantic-схемы (CreditObject, DroneInspection, StrategyResult)
│   ├── ingestion/           # Парсинг EXIF, RTK, MRK, геопривязка к кадастру
│   ├── cv/                  # CV-ядро (определение стадии 0/50/100%, материалов, ракурсов)
│   ├── engine/              # Детерминированный Decision Engine (матрица стратегий)
│   ├── gigachat_service/    # Интеграция с GigaChat API (резюме инспектора)
│   ├── report/              # Генератор «Акта проверки залога» (Приложение 1, HTML/PDF)
│   └── ui/                  # Web-интерфейс инспектора (Streamlit)
└── tests/                   # Юнит- и интеграционные тесты
```
